# Windows：Codex Proxy RS 用量适配

本适配根据 `zyycn/codex-proxy-rs` 的 **v3.35.1** 接口实现；使用客户端 API Key 查询其在服务端记录的用量，不需要管理员密码。已通过模拟接口和 Windows 界面测试，尚未连接用户的实际部署验证。

## 配置

1. 打开 VibeGauge 的 **API** 页面，滚动至底部的「额度监控 · API 密钥」。
2. 选择 **Codex Proxy RS**。
3. 填写部署地址（例如 `https://proxy.example.com`，也接受 `/v1` 地址和反向代理子路径），可选填写站点名称。
4. 填写用于调用该站点的 **客户端 API Key**，点击「测试连接」，成功后点击「保存密钥」。测试不会保存密钥。
5. 在「订阅」查看日/周额度；在 API 页的「Codex Proxy RS · 服务端统计」查看用量。后台每 **3 分钟**查询一次。

远程站点要求 HTTPS；本机回环地址允许 HTTP。请求不跟随重定向，应填写最终部署地址。反向代理必须同时开放 `/v1/usage`、`/api/auth/login` 和 `/api/key-usage/*`，并传递会话 Cookie。

## 统计范围

- 今日、近 30 天、已同步累计 Token 和请求数，输入/输出、缓存读取/写入、思考用量、趋势，以及近 30 天最近 20 次请求。
- 统计范围是当前 Key 的所有设备调用；今日边界由服务端时区决定。
- 费用标为「站点计费」，保留服务端返回的金额和费用不完整状态，不替换为本地 OpenRouter 估算。未知费用和未知请求用量不会显示为零。
- 服务端统计单独展示，不加入本地代理、Codex 日志或 Agent 汇总，避免同一请求重复计算。
- **已同步累计不等于完整历史账单**：首次只同步近 30 天，随后保存已同步的历史时间段。重复查询替换重叠时间段，不反复相加。首次同步之前以及超出查询窗口的离线缺口不会自动补齐。更换时间粒度或服务端时区时，无法完整保留的重叠边界不计入累计。
- 趋势尚未完整时保留先前累计，并提示；请求失败时保留本次运行中最近成功的数据，标明旧数据和时间。凭据被拒绝后隐藏旧报告。

## 凭据和缓存

密钥保存在 Windows 凭据管理器，Codex Proxy RS 与旧的 sub2api 登记分开保存。会话仅保留在内存中，过期后重新登录；收到 401 最多重试登录一次。服务端错误正文不直接显示，避免回显敏感信息。

`LocalDataRoot/codex-proxy-rs-history/` 下只缓存历史时间段和用量数值，按站点及密钥哈希隔离，不保存原始密钥、会话 Cookie、客户端 IP 或 User-Agent。删除已登记密钥会停止查询；数值历史文件保留供重新登记同一密钥时继续累计。

## 排查

- **404**：检查部署版本、地址前缀，以及是否只开放了 `/v1` 路由。
- **401 / 403**：检查客户端 Key 是否有效、是否允许查询用量。
- **要求跳转**：填写跳转后的最终 HTTPS 地址。
- **格式不支持**：部署接口可能与 v3.35.1 不同，需要对照对应版本的返回字段。
- **费用不完整 / 分析未就绪**：由服务端统计结果决定，等待后续同步；不会自行填补缺失金额。
