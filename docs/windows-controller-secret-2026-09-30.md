# 本机控制器密钥输入与认证验收（2026-09-30）

## 原因和修改

用户的 Gemini 卡片显示“连接表不可用”。本机只读检查确认 ClashMi 控制器在 127.0.0.1:9090 监听，未提供认证时 /version 和 /connections 均返回 HTTP 401。旧版仅通过 VIBEGAUGE_CLASH_SECRET 环境变量接收密钥，界面没有输入入口，失败提示也没有区分认证、连接和格式错误。

本轮在“系统 → 详细设置 → 网络诊断”增加控制器 secret 密码框及三个操作：保存控制器设置、测试连接、移除已保存密钥。

- 密码框遮蔽输入；保存后清空输入框，显示已保存状态。留空保存保留现有密钥，输入新值替换，删除通过独立按钮执行。
- 密钥使用 Windows DPAPI CurrentUser 加密，单独写入本应用数据目录的 clash-credential.json；features.json 不存密钥。加密记录绑定规范化后的控制器地址，不把旧控制器密钥用于另一个地址。
- 同一控制器的已保存密钥优先于环境变量，未保存时兼容原环境变量方式。移除后如环境变量仍存在，界面明确提示仍会使用它。损坏的加密记录显式报错，允许重新保存修复。
- 保存值在下一次检测时读取，不必重启。测试连接使用当前输入（空白输入框则使用已保存值或环境变量），只访问本机控制器，不保存输入，也不执行完整外网诊断。
- 控制器认证失败、404、重定向、无法连接、超时和响应格式错误分别显示。Gemini 卡片直接显示连接表失败原因；成功且有活动连接时显示链路，成功但无活动连接时仍显示等待连接，不伪造 Google 出口 IP。
- 控制器仅允许本机 HTTP 地址，支持 localhost、127.0.0.1、IPv6 回环；拒绝远程地址、URL 内凭据、路径、查询和片段。HTTP 请求不使用系统代理，不跟随重定向，不启用 Cookie。报错不展示响应原文或密钥。

## 验证

Windows 测试 114 项全部通过，0 失败、0 跳过；比原 93 项新增 21 项。此前 Core 275 项与 Proxy 26 项未在本轮重复执行，相关源代码没有本轮新增改动。

新增覆盖：加密后落盘及重读、密钥替换与删除、地址绑定、环境变量优先级、损坏记录、非法/空地址、localhost/IPv6、401/403/404/500/重定向、无效连接响应和不泄漏返回内容。

另以真实 TCP 回环监听器模拟需要 Bearer 认证的控制器，使用实际 HttpClient 传输验证：未配置密钥 → 401；保存正确密钥 → 读取 Gemini 连接链；不重启替换错误密钥 → 401。测试仅使用临时目录和虚构密钥，没有读取用户真实控制器密钥。

WPF 验证输入遮蔽、保存后清空、留空保留、移除、普通设置文件不含密钥，以及 420 像素中英文亮暗主题无横向溢出。截图为隔离测试数据，不代表用户实际已完成认证。

## 使用

新版版本号为 1.6.5-controller-preview，包含之前的 R01–R13 审计修复和设置页重排。运行新版后，在上述页面填写 ClashMi 的控制器 secret，点击“保存控制器设置”和“测试连接”。测试通过后，使用 Gemini 产生连接，再回“网络”页执行完整诊断。

通过 Start-Preview.ps1 启动时，密钥保存在预览数据目录，正常启动使用正常数据目录；两者不会互相带入保存值。真实 ClashMi 的认证成功仍需用户在新版输入正确密钥后验证。本轮没有修改代理客户端配置、读取真实密钥、终止正在运行的应用或替换已安装版本。
