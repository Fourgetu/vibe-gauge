# 本机及软路由控制器接入验收（2026-09-30）

## 交付功能

系统 → 详细设置 → 网络诊断，新增控制器 secret 输入、加密保存、测试连接、按当前地址移除密钥，以及“连接局域网软路由”和可选来源设备 IP。

用户提供的控制面板地址对应填写 `http://192.168.10.1:9090`。开启局域网选项，填写 OpenClash 控制器的 secret（若有认证），保存后测试。程序支持 Clash / Mihomo 兼容的 /proxies 与 /connections 只读接口，没有修改代理模式、分流规则、节点选择或路由器配置。

来源设备 IP 留空时读取软路由的全部活动连接，Gemini 卡片和控制器区域明确标注“软路由全设备连接表”。填写来源 IP 时，按连接 metadata.sourceIP 过滤后再展示链路，避免把其他设备的 Gemini 连接当成本机流量。缺失来源 IP 的连接不匹配过滤条件。控制器查询成功不保证当前有 Gemini 活动连接，也不把代理节点名当作 Google 出口 IP。

## 凭据与请求范围

- 密码框遮蔽输入；保存或离开时清空，不回填原值。空输入保存保留已存值；删除单独操作。
- 使用 Windows DPAPI CurrentUser 加密，按规范化后的控制器地址分别存储在独立凭据文件；普通 features.json 不保存密钥。
- 兼容前一预览版的单控制器凭据文件，新增软路由记录时保留已有本机记录。删除一个控制器的密钥不影响其他地址。
- 本机控制器仍兼容 VIBEGAUGE_CLASH_SECRET 环境变量，已保存值优先；远程软路由永远不使用这个本机环境变量的密钥。
- 默认只接受本机回环地址；开启局域网模式后允许 RFC1918 IPv4 私网和 IPv6 ULA，支持 HTTP/HTTPS。拒绝公网 IP、任意域名、URL 内凭据、查询参数、路径和片段。
- 控制器请求绕过系统代理、不跟随重定向、不启用 Cookie；HTTPS 使用正常证书校验。HTTP 适用于可信局域网，页面说明可使用 HTTPS。
- 保存值在下一次查询时生效，无需重启。“测试连接”使用当前填写值但不保存输入，不执行外网 trace 诊断。认证失败、接口缺失、连不上、超时、无效响应分别反馈；Gemini 卡片直接显示连接表失败原因。

## 验证与范围

完整解决方案 **427 项测试通过**：Core 275、Proxy 26、Windows 126，0 失败、0 跳过。Windows 较原 93 项新增 33 项控制器测试。

覆盖加密与重启读取、按地址保存与删除、旧格式迁移、环境变量隔离、非法地址、LAN 明确启用、来源筛选、全设备范围标注、HTTP 错误与响应格式。另用真实 TCP 回环模拟控制器验证认证：未配置 → 401，保存正确密钥 → Gemini 链路成功，不重启改错密钥 → 401。路由器地址测试使用可控 HTTP handler，不扫描用户局域网、不读取真实密钥。

WPF 界面检查中英文、亮暗主题、420 像素宽度、保存后密码框清空、留空保留、独立移除、筛选配置持久化及无横向溢出。截图使用隔离夹具，来源 IP 192.168.10.8 是示例，不是自动检测到的用户设备 IP。

在当前 Windows 环境对用户给出的 192.168.10.1:9090 进行了不带密钥的只读可达性检查，请求未建立成功（SocketException）。因此没有声称已在用户真实 OpenClash 上完成认证；应在能访问该软路由控制端口的电脑上填密钥并测试。
