# VibeGauge v1.5.0

Windows 功能与轻量化更新，包含 v1.4.0 之后的总 Token 展示、紧凑布局、贴顶收缩及动画和内存优化。此前的 PI-Desktop、按日期统计、自定义 sub2api、浅深色毛玻璃等功能全部保留。macOS 保留既有实现，随版本提供 Universal 构建。

## 新功能与界面改进

- **总 Token 更直观**：今日总览、各来源、PI-Desktop 当日与累计用量、近期调用、所选日期/范围、模型分布、日历提示，以及 API 汇总均增加总 Token。
- **避免重复计数**：总 Token 为归一化输入/上下文加输出；缓存和思考 Token 不重复累加。原有细分项目保留，API 与 CLI 仍独立统计；模型占比继续明确按上下文 Token 计算。
- **紧凑窗口**：默认和最小宽度调整为 420 逻辑像素，保留字体大小、手动缩放、窗口位置记忆和完整系统信息。
- **贴顶自动隐藏**：拖到显示器顶部边缘后，鼠标离开约 700 毫秒自动向上收缩，仅留 2 物理像素触发区域；鼠标移到对应边缘即可展开，拖离顶部恢复普通悬浮。
- **更平滑的收放动画**：改用渲染帧驱动和约 240 毫秒缓动，动画停止后解除渲染回调，减少重复裁剪；兼容多屏边界与显示缩放。
- 拖动、输入和模态对话框期间暂缓隐藏；悬停展开不抢键盘焦点，记忆展开位置，避免重启后窗口留在屏幕外。

## 性能与内存

- 未变化的日志不再重复分配大缓冲；复用并清理读取缓冲，在解码前过滤无关日志。
- Codex 额度只缓存解析结果，文件变化才重读；每轮仍检查新增、改写、删除及过期文件，不缓存对话正文。
- 增量缓存仅在变化时写入，统计改为单次聚合，减少历史数据复制。
- 未变化的界面行复用，后台页面在切换时使用最新数据；及时释放 WMI、进程和计划任务 COM 资源。
- **保留 5 秒刷新、全部监控与历史记录**，不使用强制 GC 或工作集清理。
- 在 20,000 条合成记录基准中，未变化的额度扫描分配从约 9.38 MB/轮降至 10 KB/轮，耗时从约 22.4 ms 降至 2.0 ms；统计校验结果一致。分配量下降不等同于常驻内存同比例下降，实际占用会随数据、页面和运行时间变化，详见[实测记录](https://github.com/Fourgetu/vibe-gauge/blob/v1.5.0/docs/windows-memory.md)。

## 升级与验证

- 升级前完成正在转发的 API 请求，再退出旧版托盘程序。安装器不会强制结束旧进程；便携版请完整解压，不要只替换单个文件。
- 现有配置和统计保留在 `%LOCALAPPDATA%\VibeGauge`，密钥仍存于 Windows 凭据管理器。
- Windows 本地验证通过 **170 项测试**，覆盖统计口径、选中日期、PI-Desktop、sub2api、代理协议与安全、日志缓存、界面复用及贴边行为。原生截图验证浅深色、拖动、缩放和收放动画。
- 发布流程在 macOS 和 Windows 构建、自测及附件上传成功后才发布正式版。
- Windows 安装包暂未代码签名，可能出现 SmartScreen/未知发布者提示；请核对来源和 SHA-256。系统不支持透明效果时使用可读的实色背景。
- 不宣称所有 macOS 功能已移植；现有[平台边界](https://github.com/Fourgetu/vibe-gauge/blob/v1.5.0/docs/windows-upstream-1.3.1.md)保持不变。

## English Summary

- Add explicit total-token counts across CLI, PI-Desktop, selected-date/model statistics, and API views without double-counting cache or reasoning tokens.
- Introduce a compact 420-pixel layout and smooth top-edge auto-hide/hover reveal with multi-monitor handling.
- Reduce repeated log allocations, cache writes, history copies, and UI rebuilding; release native monitoring resources deterministically.
- Preserve the five-second refresh interval, monitoring features, history, acrylic themes, and separate API accounting. Allocation benchmarks are not promises of fixed resident-memory savings.
