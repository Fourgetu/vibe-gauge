# VibeGauge v1.6.3

Windows Codex 账号切换与额度归属修复。解决从 Team 切换账号后，旧会话中的套餐名称仍覆盖当前登录信息的问题。保留 v1.6.2 的全部功能；macOS 功能实现不变，随版本提供 Universal 构建。

## 修复与改进

- **当前登录优先**：Pro 等套餐声明以当前本地登录信息为准，不再被旧 Team 会话覆盖。明确使用 API Key 时，不继承历史订阅套餐或额度。
- **切换账号后等待新回报**：过滤登录边界之前的额度，以及与当前已知套餐不一致的旧会话、额外额度池和耗尽事件。没有可信的新回报时显示等待，不编造 Pro 或额度百分比。
- **保护同账号刷新**：应用运行期间，同一个已识别账号正常刷新令牌，不会无故清除已观察到的额度；身份或套餐改变时更新判断边界。
- **隔离额度趋势与通知**：额度采样、预测通知和阈值通知去重按账号区分，避免沿用旧账号的速率或通知状态。保存的是不可读的身份摘要，不保存原始账号 ID 或令牌。
- **明确时间含义**：二级详情中的“采集于”改为“额度回报”，与页面的“最近扫描”区分。正常每 5 秒扫描本地数据；手动刷新也不会强制官方接口产生新的额度回报。
- **认证异常处理**：登录文件不可读时显示读取失败，不再悄悄回退成旧 Team 套餐。
- **历史 Token 不变**：不清空、重算或拆分累计 Token 账本，不改动用户账号配置与真实会话文件。

## 使用与升级说明

1. 升级前退出旧版 VibeGauge 及其代理，保留 `%LOCALAPPDATA%\VibeGauge` 中的账本和设置。
2. 在目标客户端切换订阅账号后，获取该会话的新额度回报。旧会话必要时退出，避免其继续回报旧账号数据。
3. 如果本地 `auth.json` 只提供 API Key，界面会显示 API Key；在其他浏览器、应用或远端切换 Pro，不一定更新这个本地认证文件。
4. 首次启动使用认证文件修改时间作为保守的登录边界，可能需要等待新额度回报；应用运行中的同账号令牌刷新会保留原边界。

额度日志本身不包含账号 ID，无法仅凭同套餐的并发旧会话回报完美确认归属。本次修复不是在线账号验证，也不改变此前的本机累计用量定义。详情见[账号与刷新规则](https://github.com/Fourgetu/vibe-gauge/blob/v1.6.3/docs/windows-account-quota.md)。

## English

- Prefer current local Codex authentication over historical Team/Pro session labels.
- Do not attach historical subscription quotas to API-key authentication.
- Filter pre-login and conflicting-plan quota reports; wait for fresh data instead of guessing.
- Separate quota trends and notification deduplication by account while preserving same-account token refresh behavior.
- Distinguish quota-report age from the five-second dashboard scan. Retained token accounting is unchanged.
