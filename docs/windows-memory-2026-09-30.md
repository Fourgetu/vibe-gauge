# Windows 内存优化复测（2026-09-30）

目标是在保留功能、历史记录和五秒刷新频率的前提下，降低约 150 MB 的常驻占用。本轮已经降低重复扫描分配和部分界面开销，**尚未验证真实使用场景能从 150 MB 稳定降至 100 MB**。

## 测量口径

- 用户正在运行的 `1.6.5-router-preview`：初始私有工作集 148 MiB，私有提交约 192 MiB，总工作集约 319 MiB。进程没有被停止或替换。
- 以 Windows 性能计数器 `WorkingSetPrivate` 对比常驻内存。不能把包含共享页的 `Get-Process.WorkingSet64` 与任务管理器里的私有工作集混用。
- 本文 MB 数字实际按 MiB（1,048,576 字节）计算。
- UI 测试使用两万个合成记录、真实 WPF 主窗口及正常五秒扫描。依次切换概览、系统、统计、网络、中英文、隐藏和重新显示。
- 两个进程同时运行，各自使用隔离的数据目录。每两秒记录应用指标，每约三秒由外部采样私有工作集；分析启动后第 20～70 秒。
- 第一轮先启动基线，第二轮反转启动顺序。版本、工作负载和原始报告保存在 `windows/artifacts/memory-20260930`。
- 合成测试不访问真实账号配置，不发起出口诊断，也不包含用户的完整真实日志和长时间运行状态，因此不能外推为真实环境必然低于 100 MB。

## 改动

1. 去重后的用量记录按来源复用。文件变化、读取失败、历史展开和压缩会使对应缓存失效；今日统计、时间窗口和套餐估算仍然每轮计算。
2. 账本加载时复用相同来源、模型、主机字符串以及相同的记录键。复用表有数量上限，不使用进程永久驻留的字符串池，不改变账本格式或字段值。
3. 空布局对象不再分配无用的本地化状态和属性监听；文本和绑定继续跟踪，后续添加的工具提示在打开时加入翻译。
4. 主窗口隐藏时暂停重建详情视图，后台监测、数据和托盘继续刷新，重新显示时使用最新快照。
5. 统计图表延迟到使用时创建；未变化的网络诊断复用界面控件，采集时间的分钟数变化时重新更新。

没有删除历史、缩小统计范围、降低刷新频率、强制 GC、清空工作集或设置内存硬上限。

## 核心扫描对照

同一份合成数据、预热后 12 次无变化扫描：

| 指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 每次用量扫描分配 | 1,498,661 字节 | 385,054 字节 |
| 每次用量扫描耗时 | 8.631 ms | 6.864 ms |

临时分配减少约 74.3%；**这是分配量降幅，不是常驻内存降幅**。两版统计校验值相同：

## UI 内存对照

第一轮的 20～70 秒窗口，各 13 个私有工作集样本：

| 指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 私有工作集均值 | 81.09 MiB | 74.59 MiB |
| 私有工作集范围 | 71.55～89.52 MiB | 60.07～80.64 MiB |
| 私有提交均值 | 100.33 MiB | 93.08 MiB |
| 全程累计分配 | 487,027,216 字节 | 463,268,296 字节 |
| 全程进程 CPU 时间 | 12.72 秒 | 12.30 秒 |

第一轮平均减少 6.50 MiB（约 8%），但末尾单次私有提交几乎相同。仅修改 UI 的早期试验也没有稳定内存降幅，说明短时读数受 GC 时机影响，不宜只挑最低值。

原始结果：`paired-before.jsonl`、`paired-after.jsonl`、`paired-working-set.jsonl`；复测使用 `repeat-*`。

第二轮反转启动顺序，20～70 秒各 14 个样本：

| 指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 私有工作集均值 | 79.93 MiB | 73.32 MiB |
| 私有工作集范围 | 71.58～88.03 MiB | 62.99～80.71 MiB |
| 私有提交均值 | 98.36 MiB | 91.83 MiB |
| 全程累计分配 | 518,436,656 字节 | 493,558,512 字节 |
| 全程进程 CPU 时间 | 13.17 秒 | 13.20 秒 |

复测平均减少 6.61 MiB（约 8.3%），CPU 耗时相近。两轮均支持小幅降低内存，仍不支持“真实 150 MB 已降至 100 MB”的结论。

## 功能验证

- 完整解决方案 427 项测试通过：Core 275、Proxy 26、Windows 126。
- 原有测试覆盖追加、不完整行、重写、删除后保留、恢复、历史压缩及 API 元数据。
- 新增 WPF 检查覆盖隐藏期间更新快照、重新显示立即呈现新诊断结果、语言切换；在现有 STA 界面测试中执行。
- 两个 UI 基准结束时均显示 680 次调用、659.6 万 Token，错误输出为空。
- 发布后的主程序和代理程序 `--selftest` 均通过。
- 基准代码在 `windows/tests/MemoryUiBench`；核心基准继续使用 `windows/tests/MemoryBench`。两者都使用隔离合成数据。

## 使用与限制

预览版保存为 `windows/artifacts/memory-20260930/VibeGauge-1.6.5-memory-preview-win-x64.zip`。
关闭旧版后正常启动解压目录中的 `VibeGauge.exe`，才会使用已有本地配置和真实历史；`Start-Preview.ps1` 只用于隔离界面预览，不能用来代表真实数据负载的内存。

预览版保留软路由控制器和加密密钥输入功能。此次没有修改正在运行的程序、代理进程或已有配置。下一步验证真实 100 MB 目标需要在新版正常运行、加载现有历史后持续采样；当前实验不能替代这一步。
