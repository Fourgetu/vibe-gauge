# Windows 统计页展示补齐（2026-09-30）

## 对照结论

用户指出的两处差距属实。已核对本仓库上游 `Sources/StatsTabView.swift` 的 `metrics`、`distribution`、`todayModels`，以及 `Sources/UsageHistory.swift` 的 `modelMix`：

- 上游顶部为四张 2×2 卡片；Windows 原实现把这些信息简化为文字，没有独立成本、活跃天数和缓存命中率卡片。
- 上游有新输入／输出／缓存的堆叠条和图例；Windows 原实现只有数字摘要。
- 上游模型构成按输入（含缓存）加输出计算，同名模型跨来源合并。Windows 原实现按来源分别列出模型，百分比只用上下文输入，输出较多的模型因此被低估。

本轮补齐以上展示。Windows 已有的“今日／7D／30D／全部”和点选日期功能保留；四卡、Token 分布和模型构成都使用当前选择的同一时间范围，标题明确范围。默认仍为 30D，不将所选历史范围混用为今日数据。

## 展示与统计口径

| 项目 | 实现 |
| --- | --- |
| 总 Token | 输入（含缓存）+ 输出；不重复加缓存和思考 |
| API 等价成本 | 使用本地 `prices.json`；无配置、无匹配价格、部分模型未定价有独立状态；不是实际账单 |
| 活跃天数 | 所选范围内 Token 用量大于零的日历日；零 Token 调用不增加天数 |
| 缓存命中率 | 缓存读取 / 全部输入；没有输入时显示“—” |
| Token 分布 | 蓝色新输入、橙色输出、绿色缓存；新输入 = max(0, 输入 − 缓存读取 − 缓存写入)，缓存 = 读取 + 写入 |
| 思考 | 作为输出的附加说明；不成为第四段，也不重复加到总量 |
| 模型构成 | 同名模型跨工具合并，以输入 + 输出排序并计算百分比；同一颜色关联堆叠条、图例 |
| 模型明细 | 显示总 Token、占比、缓存读取及输出；悬停保留来源、调用、输入、缓存写入和思考信息 |
| 模型数量 | 保留所有模型，不截断为前六个，避免隐藏原有明细 |
| API 代理 | 延续原有独立记账口径，不混入 CLI／桌面历史总量重复计数 |

价格估算继续使用原始按来源模型记录，显示层合并不改变定价输入。历史、日历、小时视图、Token 单位切换、日期选择和后台刷新保留。
